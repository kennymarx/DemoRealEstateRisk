# 房地产合作项目财务报表 OCR + 风险评估

自动扫描项目目录 → 大模型 OCR 识别财务报表图片 → 写入 Excel → 结合外部风险给出高/中/低三档评级。

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 准备输入（见下节）

# 3. 配置大模型（编辑 run.sh 或 run.bat 顶部三行）

# 4. 一键运行
./run.sh          # Linux / Mac
run.bat           # Windows
```

## 输入数据准备

```
projects/
├── 项目A/
│   └── 2023年财务报表/      ← 文件夹名含"财务报表/财报/报表/财务报告"即可
│       ├── 资产负债表_01.jpg
│       ├── 利润表_01.jpg
│       └── ...
└── 项目B/
    └── 财务报告/
        └── ...
```

授信报告图片放在同一合作项目目录下名为“授信报告”“授信资料”“授信材料”或包含“授信”的子目录中：

```text
projects/
└── 项目A/
    ├── 财务报表/
    │   └── ...
    └── 授信报告/
        ├── 授信报告_01.jpg
        └── 授信报告_02.png
```

并在 `risk_inputs.json` 填写开发商与项目的外部风险信息（可选）。建议把外部风险拆成带日期的事件，避免把当前信息错误套用到历史财报年度：

```json
{
    "developers": {
        "示例开发商": {
            "risk_events": [
                {"date": "2024-06-15", "type": "债务展期", "description": "境内债券展期"},
                {"date": "2025-02", "type": "评级调整", "description": "评级展望调整为负面"}
            ]
        }
    },
    "projects": {}
}
```

风险分析按财报期间逐年对齐外部事件：只有年份时，以当年 12 月 31 日作为报告时点；晚于该时点的信息不得用于该年度评级。无日期的信息视为时间未注明，不能推断为历史事实。修改 `risk_inputs.json` 中与项目相关的信息会触发该项目重新进行风险分析。

## 输出结果

```
output/
├── projects/
│   ├── 项目A/
│   │   ├── 财务报表.xlsx     # 当前项目的「明细」长表 + 「宽表」
│   │   └── 风险分析报告.json # 当前项目的独立风险报告
│   └── 项目B/
│       ├── 财务报表.xlsx
│       └── 风险分析报告.json
├── 风险信息汇总表.json       # 断点续作依据
├── 风险信息汇总表.xlsx       # 给人看，等级带红/黄/绿
├── history/                  # 汇总表自动备份（保留最近 50 个）
```

每个合作项目的财务报表与详细风险报告分别保存在 `output/projects/项目名/` 中。根目录的风险信息汇总表保留所有项目的评级索引，不替代各项目的独立报告。

授信报告综合分析会读取已有的 `output/projects/项目名/财务报表.xlsx`，不重新执行财务报表 OCR。每个项目生成 `综合风险报告.json`，根目录生成 `综合风险信息汇总表.json` 和 `综合风险信息汇总表.xlsx`。汇总结果包含项目规模/投入、已投入与剩余投入、项目状态、建设进度、待售数量和占比、尾盘判断、后续资金判断，以及授信报告未反映但财务报表显示的风险。

## 命令行参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--root` | 项目根目录 | `./projects` |
| `--output` | 输出目录 | `./output` |
| `--cache` | 缓存目录 | `./cache` |
| `--batch-size` | 单次发送图片数 | 1 |
| `--base-url` | 大模型 base url | 环境变量 |
| `--api-key` | 大模型 api key | 环境变量 |

| `--risk-input` | 外部风险信息 JSON | `./risk_inputs.json` |

| `--qps-burst` | 瞬时突发峰值 | 等于 QPS |
| `--retry-rounds` | 失败重试轮数 | 2 |

| `--analyze-credit-report` | 读取授信报告图片，并结合已有财务 Excel 生成综合风险报告 | 关 |
| `--force-rerun` | 忽略汇总表全量重跑 | 关 |
| `-v` | 详细日志 | 关 |

## 核心机制

### 1. 分批 OCR + 缓存
- 每批默认 1 张图，减少长输出截断
- 每批结果缓存到 `cache/`，文件名包含项目名、资料类型和批次/图片名，例如 `项目A_财务报表OCR_批次1_<短哈希>.json`、`项目A_授信报告OCR_授信报告页1_<短哈希>.json`
- 要求大模型返回 JSON；非正常结束或 JSON 解析失败的响应不缓存，后续运行可重试
- 旧版纯哈希缓存首次命中时会自动迁移为可读文件名
- 中途崩溃重跑时，已识别批次直接命中缓存

### 2. 大模型限流（默认 6 QPS）
- 令牌桶算法，允许瞬时突发
- 服务端返回 429 时自动指数退避
- 线程安全，未来改并发也不会超限

### 3. 断点续作
- 每个项目计算**指纹**（图片路径+大小+mtime 的 MD5）
- 指纹不变 + 上次成功 → 跳过风险分析
- 指纹变化 / 上次失败 → 自动重跑

### 4. 失败重试队列
- 单项目独立 try/except，互不影响
- 首轮结束后失败项目进队列
- 按 5s → 10s → 20s 指数退避重试

### 5. 汇总表增量备份
- 每次覆盖前自动备份到 `output/history/`
- 内容与最新备份相同则跳过
- 默认保留最近 50 个

## 人工恢复汇总表

```python
from summary_manager import SummaryManager

s = SummaryManager("./output/风险信息汇总表.json")
print(s.list_backups())                                  # 查看备份
s.restore_from_backup("./output/history/汇总表_xxx.json")  # 恢复
```

## 常见问题

**Q: OCR 结果不准？**
A: 编辑 `ocr_processor.py` 中 `OCR_PROMPT_TEMPLATE` 补充术语示例。

**Q: 服务端限流？**
A: 调小 `--qps`，或增大 `--retry-delay`。

**Q: 想并发提速？**
A: 把 `main.py` 阶段一改为 `ThreadPoolExecutor`，限流器已线程安全。

**Q: 想改回看历史某次汇总？**
A: 打开 `output/history/` 里的任意 JSON，或调用 `restore_from_backup`。

**Q: 如何单独分析授信报告？**
A: 先完成普通流程以生成各项目的 `财务报表.xlsx`，再运行 `run.bat --analyze-credit-report`。只重做授信与财务综合分析时可加 `--force-rerun`；授信图片和财务 Excel 均有缓存/指纹，未变化时会复用已有结果。该命令会把授信图片发送到配置的大模型服务。
